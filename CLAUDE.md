## Design system

Every page carries its own inline CSS. The case studies were migrated off `style.css`
(phosphor-green terminal theme) to match the homepage redesign.

- **Type:** DM Serif Display (headings) + Inter 300/400/500/600 (body)
- **Palette:** `--black #0a0a0a`, greys `#3d3d3d → #ebebeb`, `--off-white #fafaf8`,
  `--gold #b8965a` / `--gold-light #d4b87a`
- **Patterns:** 20px rounded cards, 1px `--gray-100` borders, hover lift
  (`translateY(-4px)` + `0 20px 60px rgba(0,0,0,0.05)`), `cubic-bezier(0.16,1,0.3,1)` easing
- **Layout:** `clamp(32px, 8vw, 140px)` horizontal padding; prose column capped at 720px
- **Gold shimmer** sweeps across headings on scroll

### Two gotchas worth remembering

**1. Shimmer vs. fade-in — they fight over `animation`.** `.shimmer.active` sets the
`animation` property, which *overrides* any `animation: fadeUp` on the same element. The
element then never reaches `opacity: 1` and the heading renders invisible. **Fix: put the
shimmer on an inner `<span>`, the fade on the parent.** This bit every case study hero.

**2. Animations freeze when the Browser pane is hidden.** A hidden pane doesn't composite, so
CSS animations sit at `currentTime: 0` and everything measures as `opacity: 0`. That's a
measurement artifact, not a bug — front the tab, or force `.visible` via JS before measuring.

## Layout — the editorial grid

All three case studies use a two-zone grid above 1180px, collapsing to one column below it.

```html
<section class="cs-section reveal">
  <div class="cs-section-rail"><h2>Process &amp; Outcomes</h2></div>
  <div class="cs-section-body">…</div>
</section>
```

- **`.cs-section-rail`** — 220px, sticky. Carries the section title, shrunk to ~34px since it's
  a rail label rather than a page heading. This is what stops the left side of a wide screen
  sitting empty, and it doubles as a "where am I" marker on a long page.
- **`.cs-section-body`** — everything else. Prose capped at 680px.

Inside the body, a subsection that owns media becomes a **`.cs-block`** — `.cs-block-main`
(text) beside a sticky `.cs-block-rail` (video, pull-quote, or both):

```html
<div class="cs-block">
  <div class="cs-block-main">…prose…</div>
  <div class="cs-block-rail"><figure class="cs-media">…</figure></div>
</div>
```

**Two things this gets right, both learned the hard way:**

1. **An earlier version floated media into the right margin. Don't go back to that.** A float
   lands wherever it falls in source order, so media drifts away from the text it illustrates
   and reads as randomly scattered. Pairing text and media as siblings in one block anchors
   them together.
2. **Keep `.cs-block-main` at least as tall as `.cs-block-rail`.** The row takes the height of
   the taller child, so a 600px video beside a 120px paragraph tears a 480px hole in the text
   column. Rail *shorter* than main is free — no gap. Give a block enough prose to carry its
   media, or move media to a block that has some. Current blocks run ~85–120px of rail overhang,
   which reads as breathing room rather than a hole.

The block rail is `clamp(300px, 34%, 400px)` — proportional, so a 1440px laptop doesn't squeeze
the prose column down to ~540px.

Media components: `.cs-media` (prose width), `.cs-media-wide`, `.cs-media-pair` (2-up),
`.cs-media-portrait`, `.cs-media-crop` (capped at native width so UI text never upscales).

**Portrait media belongs in a rail; wide, text-heavy screenshots belong in the body.** The
disclosure PNG is 722px of small UI text — shrunk to a 400px rail it would be unreadable, so it
sits inline in the body at native width. The videos are portrait and read fine at 340–400px.

**Use MP4, never GIF, for screen recordings.** GIF caps at 256 colours and destroys
anti-aliased UI text — a 64-colour GIF came out at 1.3 MB and looked awful where the H.264
version is 715 KB and sharp. Crop to the assistant panel rather than the whole browser window;
it removes ~60% of the pixels, all of them irrelevant chrome.

`ffmpeg` is **not** installed system-wide. It came in via `pip install --user imageio-ffmpeg`,
which bundles a static binary:

```bash
python3 -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"
```

Encode recipe (width and height must both be even or `yuv420p` fails):

```bash
ffmpeg -i source.gif -t 13 -vf "crop=W:H:X:Y,fps=20" \
  -c:v libx264 -profile:v high -pix_fmt yuv420p -crf 21 -preset slow \
  -movflags +faststart -an out.mp4
```

Videos use `autoplay loop muted playsinline` + a `poster`, with a JS guard that swaps to
`controls` under `prefers-reduced-motion`.
